需求

开发一个独立的 AstrBot 插件 astrbot_plugin_deskhand，让 LLM Agent 能通过自然语言精准操控 Windows 桌面 GUI —— 不是截图+键鼠模拟，而是走 MS UI Automation (UIA) 控件级交互。

核心用例：

用户: "把记事本第三行删掉，然后保存到桌面"
  → Agent 调用 desk_state() 拿到控件树
  → 看到 Edit[id=1] 的 Value="hello\nworld\ntest"
  → desk_type(id=1, line=3, text="") 删除第三行
  → desk_click(id=3) 点击"保存"按钮

约束

│ M1 · 不依赖视觉模型（vision optional，不做硬要求） │ M2 · 底层用 uiautomation 库（纯 Python MS UIA COM 封装），不用 pywinauto（太重） │ M3 · 独立插件，不放 devkit 工具箱 │ M4 · 控件 id 必须在多次 state() 调用之间保持稳定（用 UIA RuntimeId 做映射） │ M5 · state() 输出控制在一屏内（≤2000 token），只采集活跃窗口及其子树 │ M6 · 所有 UIA 调用必须有超时保护（UIA 碰到卡死的应用会阻塞） │ M7 · click/type 操作前做 precheck：目标控件仍存在且 enabled │ M8 · 插件格式符合 AstrBot 发布规范（metadata.yaml / _conf_schema.json / logo.png / requirements.txt） │ M9 · 必须用 uiautomation 的 UIA 后端（自动初始化 uiautomation.uia 模式）。Chromium 内核（WebView2/Electron/Edge）通过 UIA 将网页 DOM 完整暴露为控件树——button→ButtonControl, input→EditControl, link→HyperlinkControl——UIA 后端可直接穿透壳层读取网页内部所有交互元素，不需要 CDP/JS 注入等额外手段

四个引擎模块详解

scanner.py — 控件树采集（双后端自适应）

  • 默认 backend="uia" 模式，穿透 WebView2/Electron/Tauri 壳层

  • 用 uiautomation.GetRootControl() 出发，只采集当前活跃窗口

  • 递归遍历控件子树，每个控件输出: id / role / name / value[:100] / rect / enabled / children

  • WebView2/Electron 穿透：遇到 ClassName 为 Chrome_RenderWidgetHostHWND 的控件时不截断，强制深入递归其子树，即可拿到网页内部的 button/input/link/combobox 等全部交互元素

  • DOM 语义映射（Chromium UIA 自动完成）：<button> → ButtonControl，<input> → EditControl，<a> → HyperlinkControl，<select> → ComboBoxControl

  • 普通原生控件（Win32/WPF/Qt）同样以 uia 后端采集，向下兼容

  • 深度限制 max_depth=15（WebView2 路径需更深），子节点数限制 max_children=120

  • 超时保护：单窗口扫描 ≤5s（WebView2 子树更深），超时截断

  • 返回结构化 dict → desk_state Tool 用 json.dumps 喂给 LLM

actuator.py — 执行器

  • click(id, button="left", double=False, hover=False): cache 查 RuntimeId → ControlFromHandle → GetClickablePoint → win32api.SetCursorPos + mouse_event。hover=True 时只移动鼠标不点击——用于展开工具提示、悬停子菜单

  • drag(from_id, to_id=None, to_x=None, to_y=None): 起点控件 → mouse_down → 移动到终点控件/坐标 → mouse_up

  • type(id, text): 查控件 → 优先 SetValue（Edit 控件），fallback SendKeys（转义 {} \n \t）

  • type(id, line=N, text=…): 先 GetValue → split("\n") → 改第 N 行 → SetValue

  • press(keys, action="press"): action="press" 按下即释放；action="key_down" 按住不放（配合后续操作如 Shift+逐个点击多选）；action="key_up" 释放之前按住的键

  • select_text(id, start, end): 查 TextPattern → GetSelection → AddToSelection 扩展选区（或 fallback: 鼠标移动到 start 坐标 → mouse_down → 拖到 end → mouse_up），选中 id 控件内第 start 到第 end 个字符

  • scroll(id, direction, amount): 查 ScrollPattern，上下/左右滚动；若控件不支持 ScrollPattern → fallback 鼠标滚轮 mouse_event(MOUSEEVENTF_WHEEL) 在控件中心

  • window(action, hwnd=None, x=None, y=None, w=None, h=None): min/max/restore/close/set_topmost/focus/move(x,y)/resize(w,h)。默认操作当前活跃窗口

  • 每个操作前 precheck: 控件 handle 仍有效、仍 enabled

cache.py — ID 稳定性

  • UIA 控件有 RuntimeId（int tuple），在同一进程生命周期内不变

  • 首次扫描时分配自增 id，cache 存 {id: RuntimeId}

  • 后续 state() 中同一 RuntimeId 复用旧 id

  • LRU 淘汰，上限 128 条

annotator.py — 视觉反馈（可选）

  • screenshot(): PIL ImageGrab 截屏（指定窗口或全屏）

  • annotate(img, tree_state): 在截图上画控件边框 + id 标签

  • 供 vision LLM 双重确认

九个 LLM Tool

Electron / Tauri / WebView2 穿透方案

原理

Chromium 内核将网页 DOM 通过 UIA 完整暴露。屏幕阅读器（Narrator/NVDA）正是通过这一机制读取浏览器/Electron 内部网页内容。DeskHand 直接复用同一 UIA 通道，无需任何额外注入或协议。

│  │ WebView2 / Chromium 内核  │  │  ← UIA 深入穿透

def _is_chromium_host(control):
    """检测是否为 Chromium 渲染宿主"""
    return control.ClassName in (
        "Chrome_RenderWidgetHostHWND",  # Chromium/WebView2
        "Chrome_WidgetWin_0",           # 旧版 Chromium
    )


def scan_control(control, depth=0):
    node = {"id": next_id(), "role": control.ControlTypeName, ...}
    # 普通 Win32 控件可能 GetChildren() 返回空，
    # 但 Chromium 宿主通过 UIA 暴露了完整网页子树
    for child in control.GetChildren():
        node["children"].append(scan_control(child, depth + 1))
    return node
